# AI 配置与评论

AI 问片和 AI 评论共用当前模式的连接配置，不需要为了评论另外填写一套旧版 API Key。

- 新版 OpenAI 普通协议：使用 OpenAI API Key、Base URL 和模型，调用 `chat/completions`。
- 新版 Responses 协议：使用同一组 OpenAI 配置，调用 `responses`。
- 新版 Claude：使用 Claude API Key、Base URL 和模型，调用 `v1/messages`。Base URL 留空时使用 Claude 官方地址。
- 旧版模式：使用自定义 API 配置。新版 OpenAI 连接的三个字段全部为空时，也支持沿用完整的旧版自定义配置；不会把两套服务的密钥和地址混在一起。

OpenAI 兼容服务建议填写 `https://服务域名/v1`。仅填写域名根地址时，程序会自动补上 `/v1`；已有的自定义路径前缀保留。模型名称和 API Key 必须填写。

启用评论时，需要同时打开“AI 功能”和“AI 评论功能”，当前账号需要 AI 使用权限。评论生成使用当前模式的温度、输出 Token 上限和联网搜索设置。生成的内容标记为 AI 评论。

## 保存与恢复

- 评论按账号、影片名称、年份和请求条数保存到 PostgreSQL。不同账号互相隔离；默认每次生成 10 条。
- 打开评论区时只读取保存结果，不调用 AI。点击“生成”后，服务器先保存任务并立即返回任务 ID，后台继续生成；页面每两秒查询进度。
- 刷新、关闭页面或稍后重新打开同一影片，都可以读取任务状态和已保存评论。重复点击、多个页面同时生成同一影片会复用同一个任务。
- 点击“重新生成”才会发起新一轮调用。已有评论在生成期间保持可见，失败时继续保留，成功后整体替换。
- 任务状态和评论正文均以 PostgreSQL 为准。Redis 只缓存按结果版本区分的正文，过期或缓存丢失时从 PostgreSQL 恢复。
- 保存的评论不会因模型配置变化而自动丢弃，也不会自动再次收费；需要新模型的评论时点击重新生成。

后台任务由 Docker 自定义服务器在启动后自动处理，每个应用实例最多同时执行两个任务；每个账号最多排队或执行五个不同任务。若容器在执行中停止，任务会在租约到期后恢复，最长通常约两分钟。连续两次执行被中断会标记为失败，等待用户重试。上游已经收到的请求不能跨进程续传，故障恢复可能重新调用模型。

本功能依赖 PostgreSQL 与自定义 Node 服务器。部署时会自动执行 `014_ai_comment_jobs.sql`；请勿关闭 `AI_COMMENT_WORKER_ENABLED`，除非仅运行验证环境或有意暂停后台处理。

旧版本已经生成但未保存的评论无法从服务器恢复；启用此版本后生成的评论会自动保存。

缺少配置时，接口会明确提示当前服务缺少哪些字段。返回 HTML 等非 JSON 内容时，会提示检查 Base URL，而不是展示 JSON 解析异常。
