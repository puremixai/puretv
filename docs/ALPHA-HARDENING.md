# Alpha 维护与安全优化

本轮在 `codex/alpha-hardening` 分支、现有工作目录中实施，源码版本保持 `0.1.0-alpha.1`。数据库键、数据卷及已有实例配置继续沿用；验证使用独立临时数据库和容器。

## 实施范围

| 项目       | 实际改动                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| SQL 去重   | PostgreSQL 与 D1/SQLite/Turso 共用播放记录、收藏和用户设置仓储；复用已有数据库适配器处理占位符与批次事务。    |
| 数据一致性 | 设置版本比较与递增放入同一条写入；修复执行错误被吞、SQLite 批次未完整回滚、零更新计数丢失等问题。             |
| 类型       | 补齐用户 V2、分页结果、更新参数和领域能力；`db.ts` 中 `any` 的文本出现次数由 137 减至 56。                    |
| API 访问   | 登记 253 个路由的访问类别，测试真实 Next matcher、匿名和伪造 Cookie；图片及旧直播代理增加处理器内媒体鉴权。   |
| 代理出站   | Node 每次跳转检查地址并固定 DNS 结果，隔离上游凭证、限制响应大小，精确限定管理员配置的内网 origin。           |
| 播放编排   | 提取进度快照、保存队列、切集和换源协调器；同步离开前的本地进度，隔离旧请求、旧媒体事件和自动连播定时器。      |
| 工程门禁   | 按文件和规则限制 ESLint 存量警告；`src/lib` 与 API 禁止裸 console，日志实现及第三方 vendor 例外。             |
| 工具链     | Jest 与 jsdom 升至 30，适配 DOM mock；移除 Vidstack、`@vidstack/react` 和 `media-icons`，CI 使用 Node.js 24。 |
| 容器       | 完整及 Lite 镜像内置 HTTP 健康探针；Lite 增加共享状态判断的 API 入口，Compose 复用探针。                      |

## 后续调整：IPTV 默认直连

直播网页、TV 页面和客户端测速共用播放格式及地址解析。新建、导入和未设置模式的旧源默认直连，既有显式代理选择保留；仅代理播放列表的选项直接进入播放 URL，原生 HLS 和子播放列表也保留该模式。代理不因播放失败自动开启。

修正无后缀地址格式预检查对签名参数的重复解码，并在网页切台或卸载后取消旧探测、忽略迟到响应。后台增加新建时的模式选择，修正拖拽辅助节点的表格嵌套；lint 基线随已消除的三条无效禁用警告收紧至 848。

新增 61 项回归覆盖真实配置导入、路由处理器、后台组件、网页与 TV 播放器参数链路、测速及迟到响应。调整后 `pnpm check` 通过：类型检查、lint 门禁均通过，77 个测试套件、1260 项通过；14 项数据库集成因本轮未启用临时服务而跳过。

播放说明及直连限制见 [IPTV 配置](CONFIGURATION.md#iptv-直播)。本次调整未更新日常 Docker 实例，上方镜像与构建记录属于此前优化验证，未使用真实 IPTV 源实播。

## 保留的边界

- DB 只收敛上述三个高频领域，其余领域及 Redis 数据结构继续独立维护；存量 `any` 尚未全部消除。
- 播放页仍承载界面和多种播放器功能。本轮抽取进度与选择编排，不代表已覆盖所有浏览器、媒体源、弹幕和观影室的组合交互。
- 关闭页面时先保存同步本地检查点；浏览器可能终止远端请求，因此不承诺退出瞬间已完成跨设备同步。
- ESLint 存量警告仍存在；门禁防止每个文件和规则继续增长。静态日志规则不是抵御动态混淆的安全沙箱。
- SQLite、libSQL、PostgreSQL 和 Redis 使用真实本地或临时服务验证；未连接托管 D1、远程 Turso 或真实 IPTV/Bangumi 服务。
- 健康检查在 PostgreSQL 模式探测数据库与可选 Redis；其他存储模式目前只探测 HTTP 就绪。
