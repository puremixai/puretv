# 高优先级优化：搜索、配置可靠性、可选播放器模块

## 已实现

- 搜索 JSON、单源、建议、资源列表和 SSE 接口按认证账号处理，响应使用 `private, no-store`，并禁止 CDN 缓存。资源列表应用当前用户的视频源权限。
- 搜索页和播放页共用按账号及源选择区分的浏览器缓存键，缓存最长有效 5 分钟；旧的无账号缓存键不再读取。部分搜索结果不标记为完整缓存。
- PWA 的同源 API GET 请求使用 `NetworkOnly`。Service Worker 激活时移除已有的 API 缓存条目，保留静态资源和离线视频数据。
- 普通搜索和 SSE 共用搜索计划。每个请求最多同时执行 4 个源，每个 Node 进程最多 8 个源任务、16 个上游 HTTP 请求。单源后续分页并发为 2，最多读取 20 页；队列容量也有上限。
- Redis 按账号原子计数：每分钟 120 个令牌；普通搜索和 SSE 每次消耗 6 个，单源搜索和搜索建议每次消耗 1 个。超额返回 `429` 和 `Retry-After`。Redis 不可用时降级为有容量上限的进程内计数。
- 取消和截止时间传递到原生源、Emby 搜索及已启用脚本的 `ctx.fetch`。普通搜索切换关键词或离开页面会取消旧请求；SSE 断连、超时或缓冲过大时停止上游任务。
- 上游读取正文也受超时约束，单个响应最多 8 MiB；常规请求超时 8 秒、单源执行 20 秒、搜索总体执行信号 60 秒。取消操作不会写入共享的失败缓存。
- PostgreSQL 用户设置在同一条 SQL 中比较并更新版本。首次创建、带版本更新和兼容旧客户端的无版本更新均使用原子操作。
- PostgreSQL 读取失败向调用方抛错，不再伪装为空数据。配置读取失败不会创建默认配置，后续请求可以在数据库恢复后重试。
- 关闭弹幕时不下载或注册弹幕插件；关闭缩略图时不下载缩略图插件。两项可独立启用。

## 当前限制与后续工作

- 并发池是进程级；多副本会各自拥有并发额度。Redis 限流共享账号额度，故障时的本地降级额度不跨副本共享，缓存 Redis 淘汰计数键也可能提前释放额度。
- 60 秒是传递到搜索任务的截止信号，不是能强制终止任意数据库操作或自定义脚本 CPU 执行的隔离边界。任意服务端脚本仍默认关闭；脚本自行使用 Node 网络接口不经过 `ctx.fetch` 时，也不受上述 HTTP 并发池限制。
- 本轮主要解决缓存隔离、资源失控及数据覆盖风险。播放页首次加载 JS 仍约 385 kB、搜索页约 319 kB；可选插件按需加载不等于页面主包已经完成拆分。
- 下一批：继续拆分播放页和个人设置；视频源健康评分批量读取及缓存穿透合并；AI 后台任务空闲退避；图片按尺寸处理；监控指标和剩余 lint 警告治理。
